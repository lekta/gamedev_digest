### Unity (сегодня): запечённый occlusion culling объявлен устаревшим в 6.7

Новость: Unity объявила baked occlusion culling на middleware Umbra устаревшим начиная с версии 6.7.

**Вывод.** Старые проекты доживут на Umbra весь цикл 6.7, но закладываться на запечённое отсечение в новых уже нельзя: замену придётся выбирать между GPU occlusion culling, отсечением мелких мешей и собственной логикой видимости.

**Детали.** Пост сотрудницы Unity ElaineK от 9 ноября: Umbra нельзя обновлять и переносить на новые платформы, она плохо сочетается с GPU Resident Drawer, а объекты, созданные после запекания, не перекрывают другие. В новых проектах интерфейс запекания уже скрыт, в проектах с Umbra появится предупреждение об устаревании. GPU occlusion culling пока в разработке и рекомендован только для плотно инстансированных сцен; в планах — кулинг под мобильные архитектуры, общая выборка для нескольких камер и XR-вью, а также скриптуемый culling. [Unity Discussions](https://discussions.unity.com/t/1741459)

### Roslyn (вчера): три строки кода вешают компилятор C# насмерть

Новость: Значение по умолчанию, ссылающееся на собственную группу методов, уводит компилятор в бесконечное ожидание.

**Вывод.** `dotnet build` и анализ в IDE зависают без ошибки и жгут ядро: на сборочной машине это выглядит как упавший по таймауту билд, а не как ошибка в коде.

**Детали.** Issue dotnet/roslyn #86348 автора meziantou (`author_association: CONTRIBUTOR`), создан 8 ноября 15:27 UTC, метка Area-Compilers, открыт. Репро целиком — `class C { void M(object a = M) { } }`. Привязка значения по умолчанию требует естественный тип группы методов `M`, а тот читает значения по умолчанию параметров `M` — включая тот же `a`, который ещё не достроен, и поток ждёт собственную работу. На `LangVersion 9` зависания нет, компилятор отдаёт CS0019; ожидаемое поведение — CS1736. [GitHub](https://github.com/dotnet/roslyn/issues/86348)

- **.NET (сегодня): публикация одним файлом больше 2 ГиБ молча отдаёт пустой exe** — в `BinaryUtils.WriteToStream` длина сужается до `int`, на диапазоне 2–4 ГиБ значение становится отрицательным, цикл копирования выходит, ничего не записав и не бросив исключение, а `dotnet publish` при этом завершается успешно. По issue, в .NET 10 бандлер создаёт выходной файл до вызова этого метода, поэтому ошибка стала вылезать именно в пути публикации; предложенный фикс — сужать только размер чанка. [GitHub](https://github.com/dotnet/runtime/issues/137187)
