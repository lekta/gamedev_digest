В журнале смены за понедельник три записи, и все три про то, что выглядит исправным, пока не заглянешь внутрь. В .NET на Android структура из четырёх float выходит из вызова не той, какой в него вошла: исключения нет, есть неверные числа, и только в релизной сборке. Unity выпустила Input System 1.20.1 и между делом сообщила, что в ветках 6.7 и 7.0 пакет ввода больше не обновляется отдельно от редактора. ### .NET на Android (сегодня): структура из четырёх float портится между бэкендами
Новость: при AOT с LLVM на arm64 HFA-структура, переданная через стек, приезжает с мусором.
**Вывод.** Unity-сборки идут через IL2CPP и этого пути не используют, но если общий C#-код живёт ещё и в .NET-приложении под Android, стоит проверить места, где структура из нескольких float передаётся по значению рядом с фильтром исключений: ошибки не будет, будут неверные числа.
**Детали.** Issue dotnet/runtime #135197 от taublast, сегодня 07:38 UTC, метки untriaged и area-VM-meta-mono. Фильтр вида `catch (Exception e) when (...)` заставляет Mono компилировать метод без LLVM, и на стыке двух бэкендов согласие по AAPCS64 ломается: вместо `[0, 0, 1080, 138]` вызываемый метод получает `[0, 0, -3.3471348E+29, -3.2095935E+33]`, а в обратную сторону — `[0, 0, 0, 0]`. Найдено в живом приложении из Play Store на SDK 10.0.401, android workload 36.1.69 и рантайме Mono 10.0.11; с `EnableLLVM=false` всё верно, обход — передавать структуру через `in`. [GitHub](https://github.com/dotnet/runtime/issues/135197)

### Unity (сегодня): Input System 1.20.1, и в 6.7 с 7.0 пакет едет вместе с редактором
Новость: релиз целиком из исправлений, почти все — по окну Input Actions.
**Вывод.** В 6.0, 6.3 и 6.6 ввод по-прежнему обновляется через Package Manager, а в 6.7 и 7.0 его версия привязана к версии редактора — отдельно подтянуть свежий Input System там уже не выйдет.
**Детали.** Пост Pauliusd на форуме, сегодня 11:53; тег `1.20.1` в репозитории и changelog датированы тем же днём. Дословно: «For 6.7 and 7.0 Editors we've moved to a core package model which ships on a consistent basis alongside the Editor itself». В списке пятнадцать правок: обработка несохранённых изменений при закрытии окна Input Actions (UUM-154808), потеря выбранного действия при вызове выбора контрола из поля Path (UUM-151771), `OverflowException` на схеме управления с числовым именем больше `Int32.MaxValue` (UUM-145766), минимальный размер окна Input Debugger (UUM-137119). Единственное изменение поведения — из сцены убрали гизмо и иконки Input System (UUM-151780). [Unity Discussions](https://discussions.unity.com/t/release-input-system-1-20-1/1738320)

### prototype.indie (сегодня): Unity у 45,1% русскоязычных инди, больше половины работают без оплаты
Новость: инкубатор опубликовал опрос русскоязычных инди-разработчиков.
**Вывод.** Unity здесь остаётся движком по умолчанию и с большим отрывом, но оплачиваемую работу на нём в этой среде найти трудно: деньги получают участники меньшинства проектов, а второй по популярности движок — Unreal.
**Детали.** Материал Екатерины Гайфуллиной на App2Top от сегодня, 12:47; размер выборки в публикации не указан. Основной профессией разработку игр считают 46,3%, всем участникам платят 15,4% команд, части — ещё 22,2%; 72,8% тянут несколько ролей сами, 42,6% прямо предпочитают работать в одиночку, а больше 30 часов в неделю тратят 37,7%. Движки: Unity 45,1%, Unreal Engine 30,9%, Godot 13,6%, собственные 8%; главные проблемы — маркетинг 68,5%, нехватка финансирования 46,3%, публикация в магазинах 25,9%. [App2Top](https://app2top.ru/news/polovina-rossijskih-indi-komand-rabotaet-bez-oplaty-issledovanie-244298.html)

- **.NET 11 RC 1 (сегодня): SIGSEGV в обходе стека сборщиком мусора на iOS** — issue dotnet/runtime #135203 от gentledepp, метки os-ios и area-CodeGen-Interpreter-coreclr: в Release с `MtouchInterpreter=-all` и `PublishReadyToRun=true` приложение падает через секунды после старта, путь — `MethodDesc::GetSig` → `TransitionFrame::PromoteCallerStack` → `GcStackCrawlCallBack` → фаза разметки GC, а по адресу сбоя лежат инструкции AArch64, а не указатель на `MethodDesc`: «it misidentified the frame layout and read bytes out of the code stream». Обход — выключить ReadyToRun и остаться без прекомпиляции. [GitHub](https://github.com/dotnet/runtime/issues/135203)
