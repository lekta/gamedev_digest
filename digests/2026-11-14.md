# GameDev Digest — 14 ноября 2026

Unity Hub 4.0.0 пересобран заново: командный режим ампутирован и уехал в Unity CLI. У HDRP зафиксирована первая формальная метка устаревания. В C# с runtime async вскрытие показало дыру: `Span` через `await` компилируется и молча считает неверно.

### Unity (13.11): Hub переписали с нуля, командный режим вырезали
Вышел Unity Hub 4.0.0 — нативное приложение вместо прежней сборки на Electron.
**Вывод.** Если сборки на CI дёргают Hub в режиме `--headless`, обновление их сломает: эти команды переехали в Unity CLI, а старый интерфейс остался только в Hub 3.22.6.
**Детали.** В анонсе команда заявляет примерно десятикратно более быстрый старт и загрузку в четыре раза меньше — 58 МБ против 248 МБ на Windows. Unity CLI заменяет режим `--headless`, для каждой прежней команды в релиз-нотах указан аналог, а 3.22.6 объявлена последней версией ветки 3.x. Автор анонса в отдельной теме написал, что ни Tauri, ни webview в Hub не осталось и проект целиком переехал на Rust поверх Unity CLI. [Анонс Unity](https://discussions.unity.com/t/now-available-unity-hub-4-0-0/1741866)

### HDRP (13.11): пайплайн получил первую формальную метку устаревания
Hub 4.0.0 показывает предупреждение об устаревании для проектов и шаблонов на HDRP.
**Вывод.** Формально движок ещё ничего не отключил, но выбирать HDRP для нового проекта Unity теперь явно отговаривает — для новых стартов это аргумент в пользу URP.
**Детали.** Релиз-ноты говорят дословно: проекты и шаблоны на High Definition Render Pipeline показывают предупреждение об устаревании, причём для каждой версии редактора. В окне нового проекта шаблоны HDRP сортируются последними и никогда не выбраны по умолчанию. Там же в настройках появилась секция Warnings — предупреждение можно скрыть и вернуть обратно. [Релиз-ноты Hub 4.0.0](https://unity.com/unity-hub/release-notes?version=4.0.0)

### C# (сегодня): с runtime async `Span` через `await` компилируется и врёт
Разработчик нашёл, что с включённым runtime async компилятор C# не выдаёт ошибку CS4007 на ref-структуры, живущие через `await`.
**Вывод.** Любой zero-alloc код на `Span` и `stackalloc` в асинхронном методе на экспериментальном runtime async надо проверять руками: раньше такое не собиралось, теперь собирается и даёт неверный результат.
**Детали.** На SDK 11.0.100 и компиляторе `5.12.0-1.26529.118` без флага оба примера отбиваются ошибкой CS4007, с `runtime-async=on` компилируются без единого предупреждения. `foreach` по `ReadOnlySpan<int>` с `await Task.Yield()` внутри печатает 1 — цикл обрывается после первой итерации. Вариант со `stackalloc` падает: `IndexOutOfRangeException` в Debug и `NullReferenceException` в Release. Автор указывает на ранний возврат в `IteratorAndAsyncCaptureWalker.CaptureVariable` до проверки `IsRestrictedType()`. [Issue dotnet/roslyn #86469](https://github.com/dotnet/roslyn/issues/86469)
