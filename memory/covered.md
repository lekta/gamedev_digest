## 2026-09-24
- Unity и CoreCLR, часть 2 (22.09): Alex-Thibodeau, «The Path to CoreCLR #2: Embedding CoreCLR» — у CoreCLR есть только API запуска (`coreclr_initialize`, `coreclr_create_delegate`), развитого встраивания как у Mono нет; решение — нативные обёртки с идентичными Mono сигнатурами, экспортируемые из рантайма, плюс заглушки с фатальными проверками для недостающих функций, код движка при этом не менялся; формулировка автора — «dressing CoreCLR up in a Mono costume»; цена признана: опора на внутренние API dotnet/runtime и «a whole swath of GC-unsafe code» при перемещающем GC. [Unity Discussions](https://discussions.unity.com/t/1737339)
- JIT bulk write barrier (22.09): PR dotnet/runtime #134345 от EgorBo, смержен 22.09 — для копий структур с GC-ссылками до 128 байт JIT зовёт новый `CORINFO_HELP_BULK_WRITEBARRIER_SMALL` напрямую вместо загрузки размера в регистр и вызова `CORINFO_HELP_BULK_WRITEBARRIER`; бенчмарки 5-15% на структуре с 5 ссылочными полями; работает в JIT и NativeAOT, в ReadyToRun остаётся обёртка, копии >128 байт идут прежним путём. [GitHub](https://github.com/dotnet/runtime/pull/134345)
