- По диагонали: Roslyn — `is 'a' or 'b' or …` компилируется в бинарный поиск и JIT не сворачивает сравнения в один `bt` (05.11) — issue dotnet/roslyn #86322 «Suboptimal codegen for `is` pattern: binary search prevents JIT from using a bit test» автора rameel (`author_association: NONE`), прочитан своими руками через api.github.com. Метаданные по моему чтению: `created_at: 2026-11-05T11:13:39Z`, state open, меток нет, комментариев 2. ВАЖНО: фетчер отдал тело пересказом, дословных цитат НЕТ. По моему чтению: Roslyn понижает паттерн с несколькими `or`-константами в дерево бинарного поиска, JIT не складывает его в один `bt` с константной маской, а равнозначная цепочка `||` с `==` складывается; паттерн `N_0` — IL 84 байта, код 89 байт, цепочка `N_1` — IL 54 байта, код 52 байта; на одних константах паттерн, `switch`-оператор и switch-выражение дают по 77 байт против 42 у цепочки; набор, влезающий в одну маску, можно разложить на два bit test — 68 байт против 42; отсутствие `bt` воспроизводится на .NET 9, 10 и 11 RC3, на .NET 8 цепочка тоже меньше; предложение автора — отдавать линейную цепочку `==`, когда все константы влезают в 64-битное окно, для больших наборов оставить бинарный поиск; оговорка автора — на рантаймах без оптимизации JIT линейная цепочка делает больше сравнений на худшем пути. В выпуске взяты только 89 против 52 байт и список версий. [GitHub](https://github.com/dotnet/roslyn/issues/86322)
