Метаданные по моему чтению: `created_at: 2026-11-03T21:27:42Z`, `updated_at: 2026-11-03T21:28:58Z`, state open, метки area-CodeGen-coreclr и untriaged, комментариев 1. По моему чтению пересказа: чтение volatile-поля через промотированную локальную структуру переписывается local morph в обычное чтение промотированного поля с потерей флага volatile, дальше фазы объединяют повторные чтения и acquire-барьер не генерируется; в примере со структурой `Counters`, переданной по ref, на arm64 вместо четырёх acquire-загрузок остаётся одна; вариант с непромотированным параметром и `Volatile.Read` работают корректно. Фикс — PR #136940 «Keep volatile indirections of promoted struct fields» того же автора, прочитан своими руками: `created_at: 2026-11-03T22:41:27Z`, open, не draft, `merged_at: null`, база main, +80/−2 в 3 файлах; по пересказу тела автор называет это давним багом, сохранённым как quirk ради нулевых диффов, и отмечает хрупкость дизасм-тестов, которые решил оставить, поскольку инструкции ARM стабилизировались. Цитаты из отчёта разведки («A `volatile` field read through a promoted struct local is rewritten by local morph», «The non-promoted parameter version keeps the expected four acquire loads.», «a longstanding bug that was kept around as a quirk for zero-diffs at the time.») своими руками НЕ сверены и в выпуск не взяты.
