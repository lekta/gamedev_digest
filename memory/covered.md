- .NET 10 на ARM64: `k % 2` отдавал −1, потому что `cneg` вставали раньше своего `cmp` (14.10): issue dotnet/runtime #135521 от foffer, создан 09.10, метка area-CodeGen-coreclr, milestone 12.0.0 (на странице PR milestone не выставлен), закрыт 14.10 как completed, исполнители EgorBo и Copilot; страница issue и страница PR прочитаны своими руками, репро сам не гонял; дословно: «On osx-arm64, `k % 2` for a non-negative `k` returns `-1` when the result is stored into a newly allocated object», «The JIT emits the sign fix-up `cneg ..., lt` before the `cmp` that should set its flags», «`cneg` then reads whatever flags the allocation helper left behind», «The wrong values are all `-1` (odd `k` comes out negated)», «That suggests the store-pair (`stp`) combine is moving the `cmp` past the `cneg`», «So the codegen bug looks latent, and a change to the allocation helper in .NET 10 exposed it»; цифры — 21067 неверных из 55000 на 10.0.12 по умолчанию, 24902 из 55000 при `DOTNET_TieredCompilation=0`, 0 из 55000 на 9.0.20 при той же последовательности `and / cneg / stp / cmp`, «The wrong results are new in .NET 10 (10.0.0 through 10.0.12)»; «Not reproduced on linux-x64 (10.0.11)», linux-arm64 и win-arm64 не проверяли; фикс — PR #135575 «Preserve ARM64 flags dependencies during indirection reordering», влит в `main` 14.10 (коммит 929e677, auto-merge включил EgorBo 14.10 02:17), запрещает перестановку помеченных потребителей и производителей флагов в оптимизациях store-pair и post-indexed addressing, цена — два скалярных store вместо `stp`, +1 инструкция и +4 байта на метод; одобрили EgorBo и JulieLeeMSFT; отчёт по поручению Кристоффера Буусманна оформил Claude Code, патч написал агент Copilot от имени EgorBo; картинки нет.
